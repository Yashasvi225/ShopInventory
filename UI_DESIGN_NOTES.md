## Design

The supplied reference informs the inset rounded workspace, white sidebar, compact summary cards, spacious table panels, pill filters, and understated row dividers. The requested warm palette uses cream backgrounds, warm white surfaces, sage navigation and positive states, terracotta actions and warnings, brown headings, and gray-green secondary text.

`frontend/css/style.css` owns reusable color, spacing, radius, shadow, and typography tokens plus shared controls. The existing four stylesheet imports remain intact. Application, authentication, and public-page layout rules are scoped separately. The font stack uses Segoe UI, Helvetica Neue, and Arial; it adds no network font dependency.

The project has no installed icon library. `Icon.jsx` supplies consistent inline SVG stroke icons without adding a package. Navigation icons are decorative and do not change accessible link names. Account name, email, initials, and store name come from the existing authenticated session.

All seven authenticated pages share the shell and theme. Product, supplier, inventory, sales, and AI tables reuse `TablePanel`. Charts use the new palette while preserving series values and labels. Existing expiry warnings use two columns on larger screens and one column on smaller screens; all recommendations, limitations, and dismissal controls remain available.

Mobile navigation includes active-link focus, a Tab/Shift+Tab focus loop, Escape dismissal, and focus restoration. Hidden navigation and background content use the existing inert behavior. The shell adds a keyboard skip link, controls have visible focus states, table headings use column scope, and existing modal focus trapping remains intact. Tables scroll within their panels when a small screen cannot fit every column.

Measured contrast ratios: secondary text on cream 4.59:1; white primary-button text 5.64:1; active sage navigation 6.30:1; warning-pill text 6.53:1. This is a targeted accessibility check, not a complete accessibility audit.

## Four-page redesign

### Behavior and data

- Dashboard welcomes the actual authenticated retailer and shows the recorded shop name/type. Its original totals remain sourced from `/reports/dashboard`. Sales analytics group actual dated sales from the last 30 UTC days, using the existing `/sales` date filters and 500-record limit. Missing days are not fabricated. Stock health and the attention list use real `/reports/inventory` products and their existing minimum-stock rules. Recent sales and movements come from the original dashboard response. Quick links open the appropriate stock/fashion filters; detailed two-day warnings retain their existing component and behavior. The separate 30-day expiry metric is explicitly labeled.
- Products adds actual stock counts, stock filters, sorting, record counts, and client-side pagination to the existing search/category/fashion controls. All original product fields, payloads, optimistic quantity checks, and confirmed deletion remain. Clothing still requires Old Fashion/New Fashion and has no expiry control or expiry sort. Other stores retain optional expiry. Prices accept already-supported decimal values, with their original non-negative/required constraints retained. Native field validation now also displays accessible inline messages.
- Suppliers adds real record/contact counts, contact search, pagination, and direct phone/email links where values exist. All original fields and create/edit/delete endpoints remain; deletion still uses the existing confirmation. No unsupported supplier operations were added.
- Inventory adds current product quantities, actual minimum thresholds, stock-status filters, product selection, and Stock In/Out shortcuts. The original Stock Transaction dialog remains available. Shortcuts preselect the existing transaction type/product and submit the same payload to the same atomic stock endpoints. Native positive-quantity checks and backend insufficient-stock rejection remain. Movement directions are shown as signed quantities; the original positive quantity is still submitted. History is explicitly limited to the latest 200 loaded movements, and current product metadata is distinguished from historical movements.

Pagination starts at 20 rows, offers 20/50/100 rows when useful, resets with filter changes, and clamps after deletion. These are display settings; API contracts are unchanged. Overview counts describe all loaded records, while table footers describe filtered/page results. Loading/error states do not pretend to be empty results, failed reads offer retry, and optional chart failure does not erase valid dashboard totals.

The mobile focus regression found during development was corrected: dialog launch buttons remain available during list refresh, and a removed row's dialog returns focus to the page's primary action. Existing modal focus trapping and session/navigation behavior remain.

## Sales, Reports, and AI Recommendations redesign (2026-10-09)

This pass modifies only SIM_P2 and extends the established cream, sage, terracotta, and warm-brown design. No dependencies were added.

### Resulting behavior

- Sales has a structured entry dialog with current stock, applicable expiry/fashion information, decimal selling prices, calculated total, inline native validation, and the existing submission lock. Saving waits for sales/product refresh before closing and restoring focus. The POST payload and atomic stock deduction remain unchanged.
- Sales history uses the existing server-supported inclusive UTC `from`/`to` filters and 500-record limit. Search by product/SKU, sorting, and pagination operate on those returned records; visible summary cards describe the filtered records.
- Reports retains the daily, weekly, monthly, stock, low-stock, and expiry APIs. Calendar-to-date cards and summary bars are clearly separated from the independently filtered historical revenue chart and product performance table. Stock counts use actual minimum thresholds. Empty history creates no decorative series, missing dates are not filled, and deleted product references are explicitly combined.
- Chart.js remains the charting library. Currency axes/tooltips, axis titles, compact tick counts, and existing theme tokens are shared across charts. Snapshot bars are labeled as overlapping calendar summaries rather than a trend.
- AI suggestions are accessible product cards using returned quantities, stock, demand observations, urgency, and explanations. Missing optional fields are marked as not provided. Zero-quantity responses are informational; HTTP errors, HTTP 429, retry, busy, initial, empty, and real rule-based fallback states are distinct. No successful Gemini response is fabricated.
- Applicable stores reuse exactly one existing ExpiryAlerts component on the AI page, preserving polling, persisted dismissal, confidence/no-sales handling, and the separate seven-day replacement estimate. Clothing renders no expiry warnings or controls. Reorder quantities retain their existing backend logic and are not relabeled as seven-day expiry estimates.
